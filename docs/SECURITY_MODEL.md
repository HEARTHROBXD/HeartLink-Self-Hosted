# HeartLink 客户端安全模型

更新时间：2026-07-25

## 已实现的保护

- 服务器密码、RDP 密码、私钥、代理凭据、安全策略和历史命令统一保存在当前 Windows 用户的 DPAPI 保险库中，磁盘上不写入明文。
- 第一次启动必须明确选择设置 HeartLink 独立解锁密码，或明确选择无密码模式。该密码不是 Windows PIN，也不会伪装成 Windows Hello 调用；只保存 PBKDF2-SHA256 加盐校验值。
- 用户启用“安全设置与解锁密码”同步时，加盐校验值会随完整客户端快照再次端到端加密后上传。用户可选择保留本机密码、采用云端密码或同时保留两组校验值；任何一种模式都不会上传明文解锁密码。
- 同步类别可分别开关 SSH、Windows 远程桌面、代理、应用设置、安全设置和历史命令。合并为增量并集，本机独有项目不会因为云端缺失而被静默删除；未勾选类别继续只保留在各自一端。
- HeartLink 不把 RDP 密码写入 `.rdp` 文件、进程命令行或 Windows 凭据管理器。内嵌 FreeRDP 子进程通过重定向标准输入接收一次凭据；发送后关闭输入并覆写应用可控的字节缓冲。
- 锁定时立即显示覆盖整个应用的高斯模糊遮罩，同时断开 SSH/SFTP、关闭隧道、清空终端缓冲、清空命令输入、取消终端选择，并丢弃内存中的云端同步密码引用。为支持首次成功同步后的静默同步，其副本仍由当前 Windows 用户的 DPAPI 保险库保护，其他 Windows 用户或复制到其他设备的文件不能直接解密。
- 自动锁定使用风险权重：普通界面为 `1×`，终端或远程桌面界面为 `2×`，敏感内容刚复制到剪贴板时为 `4×`。权重越高，有效空闲时限越短。
- 敏感复制默认在 30 秒后清除。Windows 剪贴板序列号发生变化时不会覆盖用户随后复制的新内容；用户可以关闭该功能或调整时限。
- DPAPI 解密所得的字节缓冲、原生凭据缓冲在使用后会覆写为零；密码认证完成后会主动释放客户端持有的密码引用。
- 每个新设备为远程撤销单独生成高熵控制令牌，云端只保存摘要。撤销操作必须再次验证云端账号密码，随后立即失效该设备的 bearer 会话，并持久下发“清空 HeartLink 本机数据并退出账号”指令；指令在客户端确认完成前会重复返回。控制指令和审计只含设备/指令标识及时间，不含同步密文、密码或终端内容。

## 无法作出的保证

桌面应用在执行密码认证、发送终端输入、记录历史命令或渲染终端输出时，必须在进程内短暂得到明文。Dart `String` 是不可变对象，无法保证垃圾回收前原地覆写。因此 HeartLink 可以缩短明文驻留时间、避免不必要副本、在锁定时清空状态，但不能诚实地承诺“内存中从不出现明文”。

拥有当前用户调试权限、管理员权限、内核权限、恶意驱动、虚拟机管理权限或物理内存访问权限的攻击者，仍可能读取进程内存。应用进程无法可靠阻止权限相同或更高的恶意工具；任何声称能绝对阻止此类读取的桌面密码工具都不可信。

远程撤销依赖客户端再次上线并执行指令，不能擦除已经导出到 HeartLink 管理范围之外的文件、截图、剪贴板历史或外部备份。旧客户端未登记独立设备控制令牌时，云端只能立即阻止后续访问，不能证明其本机数据已经清除；管理后台会显示这一能力差异。

## 部署建议

- 启用 BitLocker、Windows Defender/EDR、Secure Boot 和自动系统更新。
- 日常使用非管理员账户，不在运行 HeartLink 的账户中执行来源不明的调试器、注入器或驱动。
- 离开设备时锁定 Windows；高敏感环境应使用独立工作站或受管虚拟桌面。
- 正式承载高价值生产密钥前，仍需进行独立代码审计、依赖审计、发布签名和真实攻击面测试。
